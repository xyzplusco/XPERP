# XP ERP Demo Database Plan

작성일: 2026-08-17

## 지금 데모에서 보여줄 수 있는 것

현재 Supabase에는 이미 원본 엑셀에서 만든 운영 데이터가 들어가 있다.

- 네트워크: 435명
- 회사: 463개
- 프로젝트: 195건
- 액션/태스크: 151건
- 문서 필요 항목: 245건
- 이벤트: 23건

따라서 데모의 핵심은 "예쁜 CRM"이 아니라 다음 흐름이다.

1. 대시보드에서 전체 운영량을 본다.
2. 네트워크에서 사람/회사/세그먼트/문서 상태를 본다.
3. 프로젝트에서 회사별 딜, 유형, PL/PM, 다음 액션을 본다.
4. 이벤트에서 초대/미팅/출장성 운영 항목을 본다.
5. 문서에서 NDA, 프로필, 계약, MOU 같은 미비 항목을 본다.
6. 검색에서 액션 중심으로 다음 일을 찾는다.

## DB를 정리하는 기준

XP ERP의 DB는 엑셀을 그대로 복사하는 구조가 아니어야 한다. 원본은 보존하되, 업무 단위로 재정리해야 한다.

| 업무 개념 | 주 테이블 | 의미 |
|---|---|---|
| 사람 | `people` | 파트너, 고객사 담당자, XP 내부 인력, 이벤트 참석자 후보 |
| 회사 | `companies` | 고객사, 파트너사, 투자/매각 대상, 벤더 |
| 관계/세그먼트 | `network_profiles`, `person_company_links` | 파트너 분류, NDA/프로필/위촉 상태, 소속 관계 |
| 프로젝트/딜 | `projects` | 컨설팅, 리엔지니어링, 투자/M&A, BB, 해외진출, 내부 운영 |
| 프로젝트 멤버 | `project_members` | PL, PM, 코디, 외부 참여자 |
| 주차별 업데이트 | `project_weekly_updates` | Deal list의 1월1주~8월1주 컬럼을 행 단위로 전환 |
| 이벤트 | `events`, `event_invitees` | 미팅, IR Day, 파트너데이, 출장, 간담회와 참석자 |
| 문서 | `documents`, `document_requirements` | 파일 자체와, 아직 파일이 없어도 추적해야 하는 문서 요구 |
| 액션 | `tasks` | To Go List의 실제 다음 일, 담당, 기한, 연결 대상 |
| 원본 추적 | `import_sources`, `import_records` | 어느 파일/시트/행에서 들어온 값인지 추적 |

## 파트너 리스트와 프로젝트 리스트로 만들 수 있는 것

가능하다. 이미 1차 DB는 만들었다. 다만 "완성된 업무 DB"로 가려면 다음 정리가 더 필요하다.

### 파트너 리스트에서 정리할 것

- 사람 이름 정규화
- 회사/소속 분리
- 파트너 세그먼트 부여
- NDA / 프로필 / 위촉 / XP 계정 / 계약 상태를 `document_requirements`로 전환
- 동일 인물 중복 병합
- XP 내부 인력과 외부 파트너 구분

### 프로젝트 리스트에서 정리할 것

- 회사명 정규화
- 프로젝트 유형 매핑: 컨설팅, 리엔지니어링, 투자/M&A, BB, 해외진출
- 상태 매핑: 확정, 계약임박, 논의중, 관리중, 보류, 완료, 중단
- PL/PM/코디를 `project_members`로 분리
- 주차별 업데이트를 `project_weekly_updates`로 분리
- 다음 액션을 `tasks`로 분리
- 계약서, NDA, 제안서, IR 자료 요구를 `document_requirements`로 분리

## Claude seed 파일 판단

Claude가 만든 설계 방향은 괜찮다. 특히 주차별 업데이트, 매출 계획, 이벤트 참석자 상태, To Go List 계층화는 가져올 가치가 있다.

하지만 Claude SQL은 현재 적용된 DB 컬럼명과 다르기 때문에 그대로 실행하면 안 된다. 자세한 충돌 목록은 `docs/claude-seed-review.md`를 기준으로 본다.

## 데모 직후 다음 작업

1. 프로젝트 상세 화면: 회사, PL/PM, 주차 업데이트, 문서 미비, 액션을 한 화면에 표시
2. 네트워크 상세 화면: 파트너 프로필, 문서 상태, 연결 프로젝트/이벤트 표시
3. 이벤트 상세 화면: 참석자, 발송/회신/참석 상태 표시
4. 문서 업로드/링크 보관: Supabase Storage 또는 외부 URL 저장
5. 권한/로그인: 데모 이후 Supabase Auth 사용자 생성 후 다시 활성화
