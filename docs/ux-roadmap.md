# XP ERP — UX 고도화 계획

작성: 2026-08-19 · 기준: 라이브 DB 실측

---

## 0. 진단 — 지금은 왜 "경영자 화면"인가

현재 화면은 **숫자를 보는 도구**다. 대시보드는 건수 6개를 보여주고, 목록은 전체를 나열한다.
경영진에게는 맞지만, PL·PM이 아침에 열었을 때 **"내가 오늘 뭘 해야 하는지"** 가 없다.

실측이 이 문제를 그대로 보여준다.

| 지표 | 값 | 의미 |
|---|---:|---|
| 김수민 PL 담당 | 20 / 89 | 배정된 43건 중 47%를 1명이 부담 |
| PL 미배정 | 46 | 절반 이상이 주인 없음 |
| 최근 30일 내 업데이트 | 3 | 사실상 아무도 기록하지 않음 |
| 30일 이상 정체 | 57 | 살아있는지 죽었는지 모름 |
| 파트너 구분 미분류 | 382 / 427 | 라벨 기반 필터가 작동 못함 |

**"최근 30일 내 업데이트 3건"이 핵심 문제다.** 기록이 안 쌓이면 나머지 기능이 전부 빈 껍데기가 된다.
원본 안내 시트에도 이유가 적혀 있다 — *"PL은 주간업무보고만 작성하고, 경영지원팀이 이를 확인해 Pipeline에 반영합니다."*
**이중 입력 구조다.** ERP가 주간보고 도구 자체가 되지 않으면 이 문제는 안 풀린다.

## 1. 요청하신 3건 — 설계

### 1-1. 파트너 관리 대시보드

> "파트너 탭에 현재 파트너 / 파트너 후보만 싹 모아놓은 관리 대시보드"

**문제:** 라벨(`partner_status`) 기준으로 필터하면 11명만 나온다 (파트너 7 + 후보 4). 382명이 미분류다.

**해법 — 라벨이 아니라 근거로 판정한다.** 다음 중 하나라도 해당하면 "활동 파트너"로 본다.

- 프로젝트에 PL 또는 PM으로 배정돼 있음
- 파트너계약·위촉계약·NDA 문서가 등록돼 있음
- 수동으로 구분을 지정했음

이렇게 하면 라벨 정리를 기다리지 않고 **지금 당장** 의미 있는 명단이 나온다.
동시에 "근거는 있는데 라벨이 없는 사람"을 골라내 **한 번에 분류**하는 버튼을 제공한다.

**화면 구성 (`/partners/board`)**

```
[상단]  활동 파트너 N명 · 계약 보유 N · 프로젝트 참여 N · 문서 미비 N

[표]   이름 │ 구분 │ 참여 프로젝트 │ 역할 │ 계약상태 │ NDA/프로필/위촉 │ 최근 활동
       ─────────────────────────────────────────────────────────────
       김수민 │ 임원 │ 20건 (계약6·협상7) │ PL │ ─      │ 완료·미확인·미확인 │ 8월2차
       박지희 │ 파트너 │ 3건            │ PM │ 파트너계약 │ 완료·완료·미비   │ 7월4차
```

- 이름 클릭 → 파트너 상세, 프로젝트 건수 클릭 → 그 사람 프로젝트만 필터
- **부하 경고**: 담당 건수가 팀 평균의 2배를 넘으면 숫자를 굵게 (아이콘·색 없이)
- 문서 미비는 기존 NDA/프로필/위촉 3열 그대로 재사용

### 1-2. 이벤트 참석자 — 파트너 DB에서 검색 추가

> "검색해서 그때그때 add하고, 명단에 없을 시 그자리에서 instant하게 더할 수도 있게"

Salesforce의 **Lookup + New** 패턴 그대로다.

```
참석자 추가:  [ 김수  ▾ ]
              김수민 · XP 내부 · ksm@xyzplus.co        ← 클릭하면 즉시 추가
              김수영 · 협력사 · ...
              ─────────────────────────────
              + "김수" 새 파트너로 등록하고 추가        ← 없으면 그 자리에서 생성
```

- 입력 2글자부터 파트너 검색 (이름·회사·이메일)
- 선택 시 이름·회사·직함·이메일·전화가 **자동으로 채워짐** (지금은 손으로 다 입력)
- 없으면 인라인 생성: 이름만 필수, 나머지는 나중에. `people` + `network_profiles` 동시 생성
- 기존 엑셀 붙여넣기는 **유지** — 대량 등록에는 그게 여전히 빠르다. 두 경로 병행.

### 1-3. 프로젝트 아카이브

> "이미 끝났거나 진행하지 않는 건들에 대한 archive"

**휴지통과 구분한다.** 휴지통 = 잘못 만든 것. 아카이브 = 제대로 끝난 것.

- 상태가 `완료`/`중단`이거나 구간이 `관리기업`인 건을 목록 기본에서 제외
- 프로젝트 탭에 **활성 / 아카이브 / 전체** 토글 추가 (폴더 탭과 별개 축)
- 아카이브해도 고객사 상세·파트너 상세의 이력에는 계속 보임 (관계는 끊지 않음)
- 대량 편집으로 여러 건 한 번에 아카이브

현재 89건 중 **관리기업 36 + 보류**를 접으면 활성 화면이 절반으로 줄어든다.

## 2. 더 제안하는 것 — 실무자 시점

### 2-1. 홈을 "내 업무"로 (최우선)

Salesforce Home 의 핵심은 **My Tasks / My Opportunities** 다. 전사 숫자가 아니다.

로그인 직후 보여야 할 것:

```
내 티켓 (기한 지남 3 · 오늘 2 · 이번 주 5)
내 프로젝트 (12)  ← 업데이트 안 쓴 지 오래된 순
이번 주차 업데이트 미작성 (7)      ← 바로 쓰기 버튼
나에게 배정된 문서 미비 (2)
```

관리자는 여기에 **전사 요약**이 하나 더 붙는다 (지금 대시보드 내용).
즉 지금 대시보드를 없애는 게 아니라, **개인 화면을 위에 얹는다.**

### 2-2. 주간 업데이트 작성 플로우 (이중 입력 제거)

원본 안내가 인정한 구조적 문제를 ERP가 흡수한다.

- 홈에 **"이번 주차(8월3차) 업데이트 쓰기"** — 내 프로젝트가 한 화면에 세로로 나열되고
  각 칸에 바로 타이핑 → 한 번에 저장
- 지난주 내용이 흐리게 표시돼 참고 가능
- 저장하면 `project_weekly_updates` + `projects.latest_update` 동시 갱신 → 대시보드에 즉시 반영
- **경영지원팀의 재입력이 사라진다.** PL이 여기 쓰면 그게 곧 파이프라인이다.

이 하나가 "최근 30일 업데이트 3건" 문제를 직접 겨냥한다.

### 2-3. 정체 감지

Salesforce 의 `LastActivityDate` + 정체 리포트.

- 프로젝트 목록에 **마지막 업데이트** 열 추가, 오래된 순 정렬 기본 제공
- 30일 이상 정체 건을 홈과 프로젝트 탭에서 필터로 노출
- 정체 건은 "살릴지 / 아카이브할지" 두 버튼으로 바로 처리

### 2-4. 저장된 목록 뷰

Salesforce List View 가 실무자가 가장 많이 쓰는 기능이다.

- 지금은 매번 폴더 탭 + 상태 드롭다운을 다시 고른다
- 자주 쓰는 조합을 이름 붙여 저장: "내 협상건", "이번 달 계약 예정", "정체 30일+"
- 사이드바나 탭 줄에 고정

### 2-5. 칸반 (구간 이동)

구간(협상 → 고객)이 영업 단계 그 자체다. 표에서 드롭다운으로 바꾸는 것보다
**보드에서 끌어 옮기는 게** 주간 회의에서 압도적으로 빠르다.

- 열: 미정리후보 · 협상 · 고객 · 관리기업 · 파트너협업건
- 카드: 회사명 · PL · 마지막 업데이트 · 예상매출
- 표 뷰와 토글

### 2-6. 활동 타임라인 통합

지금 프로젝트 상세는 업데이트·액션·문서·회의록이 **각각 다른 패널**이다.
Salesforce Activity Timeline 처럼 하나의 시간순 스트림으로 합치면 "이 건에 무슨 일이 있었나"가 한눈에 보인다.
(패널은 유지하되 상단에 통합 타임라인을 추가하는 방식)

### 2-7. PL 미배정 처리 큐

46건이 주인 없이 떠 있다. 원본 안내의 "미정리후보" 개념 그대로.

- 미배정 프로젝트만 모은 화면 + 담당자 칩 버튼으로 즉시 배정
- 티켓 담당자 지정과 같은 UI 재사용

## 4. 설계 원칙 (기존 유지)

- 아이콘 없음, 컬러 뱃지 없음, 마케팅 문구 없음
- 흰 표면 + 헤어라인 보더, 그린은 링크·활성·버튼에만
- 강조는 **굵기와 선**으로만 (부하 경고 등)
- 새 기능이 기존 화면을 대체하지 않고 **얹는다** — 경영진 뷰는 유지
